# 公网 IP 管理

公网 IP 管理是 QVMConsole 的核心网络功能之一，为管理员提供了对公网 IP 资源池的全生命周期管理能力。通过将公网 IPv4 / IPv6 地址灵活绑定到指定用户的虚拟机，实现外部网络对 VM 的直接访问——无论是通过 NAT 地址映射、路由直通还是桥接透传，都可以在一个统一的管理界面中完成；结合来宾同步能力，Linux 虚拟机还可以自动完成公网地址的机内配置。

## 三种绑定模式

QVMConsole 支持三种公网 IP 绑定模式，适用于不同的网络架构和业务场景。每种模式在数据包转发路径、VM 内配置要求和上游网络依赖方面各有不同。

```mermaid
graph LR
    subgraph 互联网
        IN[外部流量]
    end

    subgraph 宿主机
        direction TB
        IF[出口网卡]

        subgraph 1:1 NAT
            direction TB
            IPT[iptables DNAT/SNAT]
        end

        subgraph 经典网络-路由
            direction TB
            RT[路由表项]
        end

        subgraph 经典网络-桥接
            direction TB
            BR[OVS 网桥]
            OF[OpenFlow 防伪造]
        end
    end

    subgraph 虚拟机
        VM1[VM - 私网 IP]
        VM2[VM - 公网 IP]
    end

    IN --> IF
    IF --> IPT --> VM1
    IF --> RT --> VM2
    IF --> BR --> OF --> VM2
```

### 模式对比

| 特性          | 1 NAT                   | 经典网络-路由                         | 经典网络-桥接                 |
| ----------- | ----------------------- | ------------------------------- | ----------------------- |
| **实现方式**    | iptables DNAT/SNAT 地址映射 | 路由表项直接路由                        | OVS 网桥二层直通              |
| **VM 内配置**  | 保持私网 IP，无需配置公网 IP       | 需配置公网 IP、掩码、网关（Linux 来宾同步可自动完成） | 需手动配置公网 IP、掩码、网关        |
| **上游依赖**    | 宿主机能使用该公网 IP            | 上游需将公网 IP 路由到宿主机                | 上游交换机需允许 VM MAC 使用公网 IP |
| **兼容性**     | 最高，推荐默认使用               | 需上游网络支持                         | 需桥接直通网桥和上游交换机配合         |
| **安全组集成**   | 自动集成 VPC 安全组规则          | 通过 OVS OpenFlow 防伪造             | 通过 OVS OpenFlow 防伪造     |
| **IPv6 支持** | 不支持（IPv6 自动剔除该模式）       | 支持（路由型公网 IPv6）                  | 支持                      |

> **推荐** 默认推荐使用 **1 NAT** 模式。该模式兼容性最高，VM 保留现有 VPC/OVS 私网 IP，公网入站和出站源地址由宿主机 iptables 规则完成映射，用户无需在 VM 内做任何网络配置变更。

> **地址族与支持模式**
>
> * 公网 IP 资源同时支持 IPv4 与 IPv6 地址，页面可按地址族筛选，动态 IPv6 资源带「动态」标签
> * IPv6 地址不支持 NAT 模式：新增 IPv6 公网 IP 时系统会自动从支持模式中剔除 NAT，仅保留路由/桥接模式

## 公网 IP 配置项

新增或编辑公网 IP 时，需要填写以下配置项：

| 配置项         | 说明                    | 示例                                   |
| ----------- | --------------------- | ------------------------------------ |
| **公网 IP**   | IPv4 或 IPv6 地址，作为唯一标识 | `203.0.113.10`、`2001:db8::10`        |
| **CIDR/掩码** | 支持 CIDR 格式或子网掩码       | `203.0.113.10/32` 或 `203.0.113.0/29` |
| **网关**      | 经典网络模式下 VM 使用的网关地址    | `203.0.113.1`                        |
| **出口网卡**    | 绑定的物理网卡，留空时自动检测默认出口   | `ens3`                               |
| **支持模式**    | 该 IP 允许的绑定模式（可多选）     | 1 NAT、经典网络-路由、经典网络-桥接                |
| **状态**      | 空闲（free）或保留（reserved） | `free`                               |
| **备注**      | 用途描述或管理信息             | `Web 服务器集群出口 IP`                     |

> **CIDR 解析** CIDR 字段支持两种格式：标准 CIDR 表示法（如 `203.0.113.8/29`）和子网掩码格式（如 `255.255.255.248`）。系统会自动解析并提取前缀长度，用于生成宿主机地址配置和 VM 内网络提示。

> **出口网卡自动识别**
>
> * 出口网卡留空时，IPv4 自动检测宿主机默认路由网卡，IPv6 自动检测默认 IPv6 出口网卡
> * 若配置的出口网卡已迁入 OVS 直通网桥，且该网桥承载对应地址族的默认路由，系统会自动改用网桥作为实际出口（OVS 直连桥识别），无需重新录入资源

### 状态说明

| 状态               | 含义        | 可执行操作          |
| ---------------- | --------- | -------------- |
| **空闲（free）**     | 未绑定到任何 VM | 可绑定、可编辑、可删除    |
| **已绑定（bound）**   | 已绑定到指定 VM | 可迁移、可解绑、可预览规则  |
| **保留（reserved）** | 预留但暂不使用   | 仅可编辑，不可绑定、不可删除 |

## 公网 IP 操作

### 新增公网 IP

在公网 IP 管理页面点击「新增公网 IP」按钮，填写配置项后保存。新增的公网 IP 默认状态为空闲，支持模式默认包含全部三种模式。

> **注意事项** 新增公网 IP 时不能直接设置为已绑定状态。需要先创建 IP 记录，再通过绑定操作关联到虚拟机。

### 编辑公网 IP

修改已有公网 IP 的配置项。当公网 IP 已处于绑定状态时，不允许修改 IP 地址本身，其他字段（CIDR、网关、出口网卡、备注等）可正常修改。

### 删除公网 IP

仅空闲状态的公网 IP 可以删除。已绑定的公网 IP 需要先解绑后再删除。删除操作属于高风险操作，需要二次验证确认。

## 批量操作

公网 IP 页面支持勾选多条记录后执行批量操作，勾选后顶部出现批量操作工具栏（显示已选数量、可绑定/可解绑数量）。

### 批量新增

新增对话框支持「单条 / 批量」切换（仅新增模式）：

| 项        | 说明                                                                     |
| -------- | ---------------------------------------------------------------------- |
| **批量输入** | 多行文本框，一行一个 IP 地址                                                       |
| **共用字段** | CIDR、网关、出口网卡、支持模式、备注等整批共用                                              |
| **独立校验** | 服务端逐条归一化与校验（IPv6 自动剔除 NAT 模式），批内重复或已存在的记录跳过（skipped），单条失败（failed）不中断整批 |
| **数量上限** | 单次批量新增不超过 1000 条                                                       |

### 批量绑定 / 批量解绑

| 操作       | 参与条件          | 执行方式                                                                                 |
| -------- | ------------- | ------------------------------------------------------------------------------------ |
| **批量绑定** | 仅未绑定（空闲）记录可参与 | 统一选择用户、虚拟机与绑定模式；含 IPv6 时自动剔除 NAT 模式；提交单个异步任务，逐条绑定后**统一应用一次**规则、VPC ACL 与来宾同步，避免中间态抖动 |
| **批量解绑** | 仅已绑定记录可参与     | 危险确认；提交单个异步任务，逐条解绑后统一清理并应用规则                                                         |

批量绑定/解绑复用 `bind_public_ip` / `unbind_public_ip` 高风险二次验证。

### 批量删除

勾选多条记录后批量删除，需危险确认；已绑定的记录自动跳过（skipped），仅删除空闲记录。批量删除为同步操作，返回逐条处理摘要。

## 绑定与解绑

### 绑定公网 IP

绑定是将公网 IP 关联到指定用户虚拟机的核心操作。完整流程如下：

```mermaid
sequenceDiagram
    participant U as 管理员
    participant Q as QVMConsole
    participant V as 校验层
    participant T as 任务队列
    participant H as 宿主机

    U->>Q: 选择公网 IP，点击绑定
    Q->>U: 展示绑定表单

    U->>Q: 选择用户
    U->>Q: 选择虚拟机
    U->>Q: 选择绑定模式
    U->>Q: 填写 VM 私网 IP（可选）
    U->>Q: 点击预览规则

    Q->>V: 校验绑定参数
    V->>V: 验证模式兼容性
    V->>V: 解析 VM 私网 IP
    V-->>Q: 返回校验结果

    Q->>U: 展示规则预览和配置提示
    U->>Q: 确认提交绑定

    Q->>T: 提交绑定任务（高风险验证）
    T->>H: 创建绑定记录
    T->>H: 生成并应用 iptables/OVS 规则
    T->>H: 同步 VPC 安全组规则（如有）
    H-->>T: 规则已应用
    T-->>U: 绑定完成
```

#### 绑定表单字段

| 字段           | 说明                   | 必填  |
| ------------ | -------------------- | --- |
| **用户**       | 选择公网 IP 绑定的目标用户      | 是   |
| **虚拟机**      | 选择目标用户的虚拟机           | 是   |
| **绑定模式**     | 从该 IP 支持的模式中选择       | 是   |
| **VM 私网 IP** | NAT 模式必填，其他模式可留空自动解析 | 视模式 |

> **自动解析 VM 私网 IP** 当 VM 私网 IP 留空时，系统会按以下优先级自动解析：
>
> 1. VPC 静态 DHCP 绑定
> 2. OVS 静态主机绑定
> 3. VM 运行时网络接口 IP
>
> 如果以上均无法解析，NAT 模式会尝试自动绑定静态 IP 地址。

### 解绑公网 IP

解绑操作将移除公网 IP 与 VM 的绑定关系。提交前需二次确认，解绑后现有公网访问将中断。解绑流程会自动清理对应的 conntrack 连接跟踪条目，确保旧连接不会残留。

> **解绑影响** 解绑公网 IP 后，该 VM 的外部网络访问将立即中断。如果有业务依赖该公网 IP，请提前做好流量切换。

## 来宾同步（Guest Sync）

经典网络模式下 VM 内需要配置公网地址与路由。对运行中的 **Linux 虚拟机**（已安装 QEMU Guest Agent 且具备 `guest-exec` 能力），QVMConsole 可以自动完成机内配置，无需用户手工操作：

```mermaid
sequenceDiagram
    participant Q as QVMConsole
    participant GA as QEMU Guest Agent
    participant VM as 虚拟机系统

    Q->>GA: Ping 与能力检测
    GA-->>Q: 就绪
    Q->>GA: guest-exec 注入应用脚本
    GA->>VM: 定位主网卡（按 MAC，回退默认路由出口）
    VM->>VM: 删除旧公网地址（按状态文件）
    VM->>VM: ip addr replace 公网/32（或 /128）
    VM->>VM: ip route replace default src 公网
    VM->>VM: 写入 systemd oneshot 服务持久化
    VM-->>Q: 应用完成
```

| 要点            | 说明                                                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **持久化**       | 在 VM 内写入 `/usr/local/sbin/qvm-public-ipv4-apply`（或 ipv6）脚本与 `qvm-public-ipv4.service` / `qvm-public-ipv6.service` systemd oneshot 单元，重启后自动恢复 |
| **去重与重试**     | 按配置哈希去重，已应用的配置不重复执行；失败或未就绪时标记 pending，由后台周期任务重试                                                                                              |
| **状态反馈**      | IPv6 来宾同步状态落库并展示在绑定列表（`来宾 IPv6` 列）：`applied`（已应用）/ `pending`（等待重试）/ `manual`（需手动配置）/ `failed`（失败）                                            |
| **不适用场景**     | Windows 虚拟机、未安装 Guest Agent 或 Agent 无 `guest-exec` 能力的 VM 会标记为 manual，按配置提示手动配置                                                              |
| **IPv4 路由细节** | VM 保留私网地址作为宿主机下一跳，公网地址以 `/32` 添加并设为默认路由首选源地址；不能把跨网段运营商网关直接配为 VM 默认网关                                                                         |
| **IPv6 路由细节** | VM 配置 `/128` 公网地址，默认网关使用宿主机路由接口的 link-local 地址                                                                                               |

> **提示** 来宾同步仅处理路由模式绑定；NAT 模式无需机内配置。绑定、解绑、迁移与规则重载后系统会自动触发来宾同步，运行中的 VM 才会执行，关机 VM 会在开机后的同步周期中补齐。

## 迁移功能

迁移公网 IP 是将已绑定的公网 IP 从一个 VM 无缝切换到另一个 VM 的操作。典型场景包括 VM 替换、故障切换和业务迁移。

### 迁移流程

```mermaid
sequenceDiagram
    participant U as 管理员
    participant Q as QVMConsole
    participant T as 任务队列
    participant H as 宿主机

    U->>Q: 选择已绑定的公网 IP，点击迁移
    Q->>U: 展示迁移表单（预填当前绑定信息）

    U->>Q: 选择目标用户
    U->>Q: 选择目标虚拟机
    U->>Q: 确认提交迁移

    Q->>T: 提交迁移任务（高风险验证）
    T->>H: 更新绑定记录
    T->>H: 清理旧 conntrack 条目
    T->>H: 重新生成规则脚本
    T->>H: 应用新规则
    T->>H: 同步 VPC 安全组规则（如有）
    H-->>T: 迁移完成
    T-->>U: 迁移任务完成
```

### 迁移实现原理

迁移操作在底层等价于一次原子性的绑定关系更新：

1. 校验目标 VM 的合法性和配额
2. 更新数据库中的绑定记录（用户名、VM 名称、私网 IP、绑定模式）
3. 清理旧的 conntrack 连接跟踪条目
4. 按新的绑定关系重新生成并应用全部公网 IP 规则
5. 同步 VPC 安全组规则（如果存在 VPC 绑定）

> **模式继承** 迁移时如果未指定新的绑定模式，系统会自动沿用原绑定的模式。

## 公网 IPv6

公网 IPv6 资源以**路由型 `/128` 地址**的形式管理：宿主机为每个公网 IPv6 地址建立指向 VM 的精确路由，并通过 **Proxy NDP** 在上联网卡代理邻居发现，使上游网络无需感知 VM 的存在。

### 前缀探测与导入

拥有公网 IPv6 前缀（如运营商分配的 /64、/56）时，可将前缀批量导入为可分配的 `/128` 资源：

| 步骤       | 说明                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------- |
| **探测**   | `GET /network/public-ips/ipv6-prefixes`（可指定上联网卡，留空自动检测默认 IPv6 出口），读取网卡全局 IPv6 地址并按前缀去重，附带默认 IPv6 网关 |
| **导入**   | `POST /network/public-ips/ipv6-prefixes/import`：指定上联网卡、前缀、生成数量（1-4096）与备注；前缀必须来自探测结果（防伪造）           |
| **地址生成** | 主机位由 `sha256("qvm-public-ipv6:<前缀>:<序号>")` 确定性填充，重复导入同一前缀不会生成重复地址                                   |
| **导入结果** | 生成 `auto_ipv6=true` 的 `/128` 空闲资源（支持模式为路由），仅登记为可分配资源，不立即上宿主机地址；列表中带「动态」标签                           |

### 动态前缀同步

动态公网 IPv6 前缀（如 SLAAC/隐私前缀）可能随上游重新分配而变化。面板内置前缀监控器：

* 启动后按 `public_ipv6_sync_interval_seconds`（默认 60 秒，范围 10-3600，系统设置 → 存储与网络）周期检测上联网卡前缀
* 前缀变化时**保留每个已绑定地址的主机位**，原位更新 `/128` 地址、绑定快照，并重写 Proxy NDP、精确路由、conntrack、VPC ACL 与端口安全
* 来宾同步状态重置为 pending，由后台任务在 VM 内应用新地址

> **动态前缀注意事项** 上游前缀变化后外部到 VM 的 IPv6 连接会短暂中断（需重建路由与邻居代理）；若 VM 内应用由来宾同步完成，新地址会在下一轮同步中写入 VM。

### IPv6 宿主机规则要点

| 规则            | 说明                                                                      |
| ------------- | ----------------------------------------------------------------------- |
| **网关地址**      | 宿主机路由接口配置 `/64` 网关地址；接口无 link-local 地址时自动生成稳定的 `fe80::` 地址              |
| **精确路由**      | `ip -6 route replace <公网>/128 dev <路由接口>`                               |
| **Proxy NDP** | 上联网卡开启 `accept_ra=2`、`proxy_ndp=1`，并添加 `ip -6 neigh replace proxy <公网>` |
| **转发放行**      | ip6tables FORWARD 链放行该地址的入站/出站流量                                        |

## 规则预览与重载

### 预览规则

对于已绑定的公网 IP，可以查看当前绑定对应的 iptables 命令和 OVS 流表规则，方便管理员核验规则正确性。

### 试算规则

对于未绑定的公网 IP，可以通过「试算」功能填写目标绑定参数，在不实际执行的情况下预览绑定后的规则效果。试算结果包含：

* 将要执行的系统命令列表
* VM 内需要配置的网络信息提示
* 潜在的警告信息（如上游网络依赖）

### 配置提示

系统会根据绑定模式自动生成 VM 内需要配置的网络信息：

| 模式          | 配置提示内容                            |
| ----------- | --------------------------------- |
| **1 NAT**   | 提示 VM 内保持私网 IP 不变，公网 IP 通过 NAT 映射 |
| **经典网络-路由** | 提示 VM 内需配置的公网 IP、子网前缀和默认网关        |
| **经典网络-桥接** | 提示 VM 内需配置的公网 IP、子网前缀和默认网关        |

### 重载规则

## 实现原理

### 1 NAT 模式

1 NAT 模式通过 iptables 的 DNAT 和 SNAT 规则实现公网地址与私网地址的一对一映射：

```mermaid
graph LR
    subgraph 入站流量
        EXT[外部客户端] -->|目标: 公网 IP| DNAT[PREROUTING DNAT]
        DNAT -->|目标改为: 私网 IP| VM_IN[VM 收到流量]
    end

    subgraph 出站流量
        VM_OUT[VM 发送流量] -->|源: 私网 IP| SNAT[POSTROUTING SNAT]
        SNAT -->|源改为: 公网 IP| EXT_OUT[外部网络]
    end
```

* **DNAT 规则**：在 PREROUTING 链中将目标地址为公网 IP 的入站流量重定向到 VM 的私网 IP
* **SNAT 规则**：在 POSTROUTING 链中将源地址为 VM 私网 IP 的出站流量替换为公网 IP，且插入在通用 MASQUERADE 规则之前以确保优先匹配
* **FORWARD 规则**：为非 VPC 管理的 IP 补充基础转发放行规则
* **宿主机地址**：按公网 IP 和 CIDR 前缀将地址添加到出口网卡，确保宿主机能响应 ARP

### 经典网络-路由模式

通过在宿主机路由表中添加路由项，将公网 IP 直接路由到 VM 所在的 OVS 网桥端口：

* IPv4：添加 `ip route replace <公网IP>/32 via <VM私网IP> dev <网桥>` 路由表项
* IPv6：添加 `ip -6 route replace <公网IP>/128 dev <路由接口>` 精确路由 + Proxy NDP（见上文公网 IPv6）
* 配合 OVS OpenFlow 防伪造规则，限制 VM 端口只能使用已绑定的公网 IP
* Linux 虚拟机可通过[来宾同步](#来宾同步guest-sync)自动完成机内地址与路由配置

### 经典网络-桥接模式

通过 OVS 网桥实现二层直通，VM 直接在二层网络上使用公网 IP：

* 不添加额外的路由表项
* 配合 OVS OpenFlow 防伪造规则，确保 VM 端口只能使用授权的公网 IP

### 防伪造机制

经典网络模式（路由和桥接）会为 VM 的 OVS 端口写入 OpenFlow 流表规则，防止 IP 地址欺骗：

| 流表规则                       | 优先级 | 作用           |
| -------------------------- | --- | ------------ |
| 允许 VM 端口发送已绑定公网 IP 的 IP 包  | 240 | 放行合法 IP 流量   |
| 允许 VM 端口发送已绑定公网 IP 的 ARP 包 | 240 | 放行合法 ARP 流量  |
| 丢弃 VM 端口的其他 IP 包           | 230 | 阻止 IP 源地址伪造  |
| 丢弃 VM 端口的其他 ARP 包          | 230 | 阻止 ARP 源地址伪造 |

> **与端口安全的关系** 上述防伪造流表仅在**全局端口安全关闭**时由公网 IP 模块直接生成；开启端口安全后，端口身份校验统一由端口安全流水线负责（见 [端口安全](/docs/tech/network/port-security)）。

> **规则生成时机** 防伪造流表规则的生成依赖 VM 的运行态 OVS 端口信息。如果 VM 未运行或无法获取 ofport，规则脚本会保留注释提示，VM 启动后可通过「重载规则」重新应用。

### 规则持久化与恢复

所有公网 IP 规则通过脚本持久化到文件系统，确保宿主机重启后规则不丢失：

| 文件路径                                  | 用途        |
| ------------------------------------- | --------- |
| `/etc/kvm-console/public-ip/rules.sh` | 当前生效的规则脚本 |
| `/etc/kvm-console/public-ip/backups/` | 历史规则备份目录  |

每次应用规则前，系统会自动备份当前规则脚本到 backups 目录。服务启动时会根据数据库中的绑定关系重新生成并应用规则，实现规则的自动恢复。

规则脚本的执行流程：

1. 清理面板托管的 iptables 规则（按注释标记匹配删除）
2. 清理面板托管的 OVS OpenFlow 流表规则（按 cookie 匹配删除）
3. 清理面板托管的宿主机公网地址
4. 启用 IP 转发（`net.ipv4.ip_forward=1`）
5. 按绑定关系逐条生成并执行规则

## 配额管理

每个用户的公网 IP 绑定数量受配额限制（`max_public_ips` 字段），防止资源滥用：

| 规则                   | 说明                        |
| -------------------- | ------------------------- |
| 管理员无限制               | 管理员角色不受配额限制               |
| `max_public_ips` 为 0 | 表示无配额限制                   |
| 绑定前检查                | 每次绑定和跨用户迁移前，系统自动检查目标用户的配额 |
| 配额不足提示               | 返回已用数量和上限信息               |

> **配额检查** 配额检查在绑定和迁移操作时执行。如果目标用户的公网 IP 数量已达到上限，操作将被拒绝并提示当前使用情况。

## 前置条件

使用公网 IP 功能前，请确保宿主机满足以下条件：

| 模式             | 前置条件                                                             |
| -------------- | ---------------------------------------------------------------- |
| **1 NAT**      | 宿主机能使用该公网 IP；上游允许该 IP 路由到宿主机，或允许宿主机出口网卡响应该 IP                    |
| **经典网络-路由**    | 上游把公网 IP 或公网段路由到宿主机；VM 内需要配置公网 IP、掩码和网关（Linux 可由来宾同步自动完成）        |
| **经典网络-桥接**    | 已创建桥接直通网桥；上游交换机允许多 MAC 或允许 VM MAC 使用该公网 IP；VM 内需要手动配置公网 IP、掩码和网关 |
| **路由型公网 IPv6** | 上联网卡获得公网 IPv6 前缀；上游支持 Proxy NDP 或将前缀路由到宿主机                       |

> **来宾同步前置条件** 使用自动来宾同步需要 VM 为 Linux、已安装并运行 QEMU Guest Agent，且 Agent 支持 `guest-exec`；不满足时绑定列表会提示手动配置。

## 故障排查

| 现象                | 排查方向                               |
| ----------------- | ---------------------------------- |
| 公网入站不通            | 在页面预览规则，确认 DNAT/SNAT 已生成；检查安全组是否放行 |
| 出站源 IP 不正确        | 确认 SNAT 规则在通用 MASQUERADE 规则之前      |
| 经典网络 VM 无法联网      | 确认上游是否支持对应的路由或桥接条件                 |
| VM 启动后防伪造未生效      | 点击「重载规则」，让系统重新识别 VM 的 OVS ofport   |
| 解绑后仍能 ping 通公网 IP | 确认解绑任务已完成；若仍通，检查宿主机出口网卡是否残留该公网地址   |
